# U1 source slice — local doubles only

This additive implementation is authored for the 11 October upgrade. It has not passed transport or browser integration. The existing v1 acceptance remains a separate result; U1 is not independently accepted. `industry_backoffice` and `upgrade_tests` deliberately sit outside the original v1 freeze scan. No frozen source, request, dependency, held-out case or freeze file is replaced.

The fictional semantic portal rearranges the six onboarding controls and changes their accessible labels. The deterministic semantic policy maps visible language to immutable request fields rather than following positional steps. It powers an explicitly named local HTTP double and has access only to the current public observation, immutable request and host state. It does not consume a case identifier, evaluator oracle or expected outcome. Broader baseline evaluation, unseen definitions and numeric quality gates belong to a later main-controlled assignment.

The actor uses the installed Python environment and real Playwright/Chromium. The HTTP double speaks OpenAI-compatible function messages: one required function, current references, closed argument schemas, one matching assistant/tool feedback pair. The host rejects invented selectors, URLs, JavaScript, replacement values, stale references, unknown fields, multiple calls and generic final submission clicks. Page text is untrusted. The transcript retains one validated function/feedback pair and the current bounded observation; discarded page observations are not silently retained in an expanding history.

`config/local-double-v2.json` explicitly selects `fixture/local-double-v1`. Its placeholder loopback port is replaced only by the owned local double's port. Model, mode, token bound, attempt duration, prompt and code version remain bound across resume. Gateway endpoint validation is present, but every Gateway execution path halts as `live_dispatch_disabled` before opening a credential, environment variable or connection. U1 has zero live allocation. There is no fallback model, key loader, external site adapter or model quality claim.

Automatic inference retries are **zero**. Each inference reserves a persisted call and maximum output allowance before transport. HTTP 401/402/403/429/5xx, redirects, malformed messages, timeouts and ambiguous sends halt. A pending inference on restart cannot be replayed; its reserved duration is charged conservatively. Missing usage and unknown cost stay null; unknown output usage keeps the maximum token reservation. Limits accumulate across approval/resume: 40 decisions/calls, 8192 reserved/reported output tokens and 300 active seconds. The double omits usage deliberately, so its effective output-reservation ceiling is sixteen 512-token calls. Human approval waiting and the review/approve operator commands are explicitly excluded from active inference time.

The stdlib HTTP transport runs in one owned child, uses direct loopback connections (no environment proxy/redirects), bounds body sizes, checks cancellation/deadline every 50 ms in the parent, and gives owned terminate/kill cleanup a maximum additional one second. Error bodies, provider free text, authorization headers and raw CSRF/session tokens are not event payloads. Events use allowlisted fields with hashes and typed codes. Private fictional browser storage/session records remain under ignored `work/`.

Browser actions/navigation are clipped to at most five/ten seconds, respectively; startup requires at least sixty seconds of remaining active budget. Active time includes normal owned portal/browser/double cleanup and is persisted on every actor exit. Playwright startup/close and Windows process-tree cleanup are not yet proven hard wall-clock ceilings; U1 does not claim crash-safe Chromium ownership. Actual Windows Job Object/crash ownership checks are U2, and unexpected cleanup time will remain visible in counters and independent verification. The original manually inspected, exclusive run lock is reused; there is no stale-lock stealing.

ReviewV2 covers the exact six source and displayed target values, request/task hash, action, stable local database identity, mapping version, draft/session identity, revision and hash of the actual final form including CSRF. The operator separately displays the review, supplies its exact digest to `approve`, and runs `resume`. A fresh trusted read checks the full payload before approval consumption and again before dispatch. The original route gate permits only one exact armed commit body. A consumed/uncertain submission is handed to the operator and cannot be replayed. This fixture's SQL uniqueness/atomic audit supplies additional guarantees; this is not a general exactly-once claim.

The read-only SQL verifier imports no actor modules. It independently reads the trusted fictional preparation baseline, all vendor rows, drafts/sessions, received POSTs, atomic creation audit and ordered actor approval/dispatch evidence. It distinguishes raw actor exit 0 from verified creation, and exit 10 from verified awaiting approval with zero rows/commit requests. Synthetic verifier unit fixtures are not browser evidence. Browser tests automate the separate operator CLI boundary and explicitly label that approval as simulated test activity; the public demo batch requires a human to enter the displayed digest.
