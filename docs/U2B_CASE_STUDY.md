The former macro is historical context. `semantic-rules-v2` uses current labels/descriptions/context/options and public development vocabulary, without fixture IDs or hidden target field names. It runs through the same action/review guards and budgets as the provider policy. The local comparator is an HTTP double, so paired results will measure exposed mechanical/semantic capability, not model intelligence. All losses and ties will be published without post-score tuning.

The evaluator checks full local SQL state rather than trusting actor text. Complete intended/attempted/verified denominators, safe handoffs versus creations, wrong/unauthorized/duplicate effects, unknown usage/cost and partial runs remain distinct. Native development checks must pass before capability freeze. Pure simulations are labeled as such. No repeated task, ERPNext contract probe or quality-negative corruption becomes a new capability task.

Tradeoffs remain explicit: bounded semantic matching can hand off on novel or ambiguous labels; local full-state audits cannot prove remote hook effects; hashes bind supplied evidence but do not attest server identity; injected uncertainty is not abrupt crash evidence. Accepted U1/U2-A manifests and failures remain unchanged. Original native resource sampler gaps and unknown transient maxima remain historical limitations. No actual human approval, paid inference, real sandbox creation or production deployment has been demonstrated by this source slice.

All new tasks/test fixtures/adapter code are authored MIT material. The separately researched ERPNext/Frappe licenses and versioned sources remain attributed in the U2-A source ledger; no upstream runtime is bundled. The pending reviewer walkthrough is development evidence, frozen paired capability evaluation, retained failures and independent full-state audit, followed only by separately authorized unseen/model/sandbox work.
